# 吃什么 · 轻量 Demo

已按「设计语言与视觉规范 v1.1（图片优先与滑动交互）」、「轻量 Demo 开发方案」及当前 PRD 实现。原生 HTML / CSS / JavaScript，12 道虚构菜品，全部照片随网页提供；无需安装依赖、登录或配置密钥。首页只保留图片、条件和入口，主图会在本地菜品照片之间自动轮换。

## 打开

在 `D:\WTE` 运行：

```powershell
node demo/serve.cjs
```

浏览器访问 **http://127.0.0.1:4173**。服务默认监听本机所有网络接口，同一局域网的其他设备可使用本机局域网 IP 访问，例如 `http://10.63.87.80:4173`。按 Ctrl+C 停止前台服务；端口已被占用时，可用 `node demo/serve.cjs 4174`。

如果只需要本机访问，可运行 `HOST=127.0.0.1 node demo/serve.cjs`（PowerShell 使用 `$env:HOST='127.0.0.1'; node demo/serve.cjs`）。

没有 Node.js 时，也可以：

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory demo
```

这是发送静态文件的预览服务，没有业务接口。也可将 `demo` 目录中的 `index.html`、`styles.css`、`app.js`、`core.js`、`data.js` 与 `assets` 整体放到任意静态托管服务；无需构建。`qa` 和文档不必上传。本次没有发布到公网。

同一 Wi-Fi 下如需手机预览，可在单独终端运行 `python -m http.server 4174 --bind 0.0.0.0 --directory demo`，使用电脑的局域网 IP 加 `:4174` 访问。电脑防火墙需允许该端口；手机的 localhost 指向手机自身。

### 临时公网预览

本机安装了 Cloudflare Tunnel 时，可以把本地 Demo 临时暴露到互联网：

```powershell
node demo/serve.cjs
cloudflared tunnel --url http://127.0.0.1:4173 --no-autoupdate
```

命令会生成一个 `trycloudflare.com` 地址。该地址不需要账号，但没有 uptime 保证，停止 `cloudflared` 或重启后会失效并重新生成；正式长期托管应使用 GitHub Pages、Cloudflare Pages、Netlify 或 Vercel 的账号部署。

## 体验路径

1. 首页自动读取默认出发点，并根据当前时间选择最近的示例餐次；用户可以手动更改出发点。
2. 冷启动按价格 → 距离 → 忌口三段呈现散落卡片；左滑卡片剔除，右滑卡片保留，也可以点击或用左右方向键完成。价格和距离保留“不考虑”卡片，忌口卡片直接显示辣、海鲜、香菜、葱蒜、牛羊肉，并支持手动输入。
3. 三段排除完成后才显示“开始选这一顿”。进入推荐后，左滑或点 × 换一个，右滑或点 ✓ 选定。可用回弯箭头撤回最近一步。
4. 点图片右上角 ⓘ 看推荐理由、完整位置、配料说明，或调整本顿排除条件；“我自己选”可回看所有合格候选。
5. 选定后查看示例文字路线，可展开选饭体验反馈；“预览餐后反馈”是单独标记的模拟记录。
6. 底部展开“演示工具”，直接看空结果、连续拒绝、候选耗尽、坏图、未知营业、本次记录和重置。

自动换卡不会循环旧菜；约束不会被悄悄放宽。条件变化后旧撤回失效；关闭详情、查看路线不影响卡片或计时。接受后撤回回到刚才那一道，首次认可时间保留。两个入口均为演示体验，不计作真实市场验证。

## 保存与反馈

- 当前会话、上次选择、反馈、少量本地动作存于当前来源的 `localStorage`，键为 `chishenme.demo.v1`。端口或浏览器变化会成为独立记录。
- 刷新保留当前流程和起始时间。重新打开时若已 30 分钟无操作，则回到新一顿入口，同时保留最近一次选择。
- 开始新一顿清除价格、距离、忌口排除和已看集合，保留出发点与上次选择；餐次重新按当时系统时间判断。
- 正式餐后入口自动提示条件为：认可后至少 2 小时且不超过 7 天、未反馈、未自动提示；以非阻塞卡片出现。上次选择中可主动补记或修改“未知”。
- 模拟餐后反馈单独保存，不覆盖正式回答；首页也能直接预览，不会伪造一条认可。
- 反馈和报错**不会上传**。讨论时需由体验者自行分享截图或内容。本版没有跨用户统计、来源归因和留存报表。
- “演示工具 → 清除本机记录”二次确认后重置。存储不可用时仍可完成当前页面的流程，会明确提示无法持久保存。

## 修改菜品与界面

| 文件 | 内容 |
|---|---|
| `data.js` | 菜名、品类、价格、两个出发点步行时间、忌口标签、餐次、是否可用、照片和位置 |
| `assets/*.webp` | 本地照片；素材出处见 `assets/SOURCES.md` |
| `core.js` | 筛选、随机排序、条件摘要、事实理由与回访时间规则 |
| `app.js` | 页面、状态、撤回、滑动、弹层、反馈与本地保存 |
| `styles.css` | 设计规范色彩、布局、适配和减弱动效，目录独立可用 |
| `index.html` | HTML 入口、无构建脚本加载 |
| `serve.cjs` | 可选本地静态服务，不属于业务后端 |

修改 `data.js` 后刷新即可。菜品 ID 要唯一且稳定；图片路径相对于 `index.html`。价格会按 ¥12 以下、¥13–18、¥19 以上分为低价 / 实惠 / 精致，距离按 5 分钟内、6–10 分钟、10 分钟以上分为近 / 适中 / 远。`spicy:false` 表示已知不辣；手动忌口会按已知关键词（例如花生、虾、辣）和示例配料做概念筛选，不能作为过敏判断。`available:false` 或 `supply:'closed'` 永不进入候选。

若删除或重命名已有菜品 ID，先清除浏览器记录，避免旧会话引用失效。修改颜色和版式可从 `styles.css` 开始，不需要构建。
